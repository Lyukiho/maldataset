# BODMAS 修复样本：静态筛查与 IDA 试点结论

## 范围

- 修复副本：`D:\bodmas_malware_dataset_batches_ida`
- 样本数：5,000（PE32 4,886；PE32+ 114）
- IDA：9.0 RC1，`idat.exe` + Hex-Rays，纯静态分析，未执行样本
- 全量静态清单：`bodmas_static_triage_5000.csv`
- IDA 试点明细：`ida_pilot_results.csv`

补丁保留的 `Subsystem=0` 没有阻止 IDA 识别 x86/x64、建立函数或调用 Hex-Rays。当前影响反编译质量的主要因素是加壳、压缩和异常控制流，而不是 Subsystem。

## 全量静态筛查

5,000/5,000 均已成功解析。启发式结果如下：

| 指标 | 数量 | 比例 |
|---|---:|---:|
| 疑似加壳/压缩 | 2,234 | 44.7% |
| 含可写且可执行节 | 2,457 | 49.1% |
| TLS 目录 | 1,193 | 23.9% |
| .NET | 114 | 2.3% |
| Authenticode 目录 | 32 | 0.6% |

壳特征与家族强相关：Benjamin 100%、Dinwod 98.6%、Wacatac 89.8%、Sfone 70.8%，而 Small 只有 2.2%、Wabot 11.9%。若随机按文件切分，模型很容易通过壳或家族模板“猜标签”，不能证明具备恶意语义识别能力。

静态筛查脚本原先有 3 个 Upatre 样本因为数据目录表少于 15 项而越界；现已改为对合法的截短目录表返回“目录不存在”，全量复核无错误。

## IDA 试点

试点包含 15 个样本，覆盖 x86/x64、疑似加壳/未加壳及多个主要家族。全部在 IDA 9 中完成加载尝试：

| 质量组 | 数量 | 含义 |
|---|---:|---|
| `pseudocode_candidate` | 8 | 能恢复有用函数，所选函数均成功反编译 |
| `unpacking_or_obfuscated` | 6 | 主要看到壳、解压或极小 stub，不代表最终 payload |
| `unusable` | 1 | 未恢复出函数 |

8 个候选样本共恢复 3,180 个函数，按排序最多选择每文件 48 个函数，共得到 255 个可用伪代码函数。样本规模差异很大：Berbew 只有 1 个函数，而 Mira 有 1,109 个、GandCrab 有 966 个。因此整文件拼成单一长文本并不合适。

代表性现象：

- Wacatac x86 与 Dinwod 试点都只恢复 5 个函数、747 条指令、2 个导入，核心是解压和动态解析；它们更像共享/相似的包装层。
- Wacatac x64 只有 1 个 885 指令、150 基本块的大函数，出现动态解析与内存权限修改，反编译结果仍主要是 unpacking stub。
- Sfone 有导入和字符串，但 IDA 未恢复出任何函数，不应强行送入伪代码分类器。
- Upatre 没触发基于节熵的静态壳规则，但只恢复 2 个函数，其中一个 300 条指令；说明必须把 IDA 函数拓扑和反编译质量纳入 gate。
- 未明显加壳的试点能提取到网络、持久化、反分析、动态解析和内存权限修改等证据。例如 Wabot 命中网络行为，Vools 同时命中反分析、动态解析、内存权限和持久化。

上述行为类别只是函数排序和可解释性特征，不是恶意标签本身；很多良性程序也会调用相同 API。

## 推荐模型

不建议第一版训练生成式聊天模型。更合适的是约 125M 参数的代码/自然语言预训练编码器（如 CodeBERT 或 UniXcoder）加分层多实例分类头：

1. **IDA 质量 gate**：根据函数数、反编译成功率、最大函数规模、节/导入异常、正栈指针和壳警告，将样本路由到 `semantic`、`packed_stub` 或 `unusable`。
2. **函数选择**：丢弃库函数和 thunk；按入口可达性、敏感 API、字符串引用、调用者数量和 CFG 复杂度选择 24--48 个函数。
3. **函数编码**：输入规范化伪代码，同时保留 API 名、字符串类别、基本块/调用边等标记。地址、临时变量名和无意义大常量应归一化。
4. **样本聚合**：每个函数单独编码，用 attention/MIL 聚合为 PE 表示，再融合少量 IDA 全局特征。不要把恶意文件标签直接赋给其中每个函数。
5. **双头输出**：一个头判断恶意概率，一个头判断分析可靠性/加壳状态；输出贡献最大的函数、API 和字符串作为证据。

对 `packed_stub`，第一版应返回低置信度或单独使用壳特征分类，不能声称看到了 payload 语义。若必须强制二分类，可以融合静态头，但评测必须单独报告 packed/unpacked 两组。

## 数据划分约束

当前 `dataset.csv` 有 2,179 条：良性 747、恶意 1,432；新增 BODMAS 5,000 条都是恶意样本，不能单独训练恶意/良性分类器。建议：

- 按来源、家族和近重复簇分组划分，禁止同家族模板或同一壳簇跨 train/test。
- BODMAS 不要全部直接并入训练集；先去重并按家族/壳状态分层采样，否则类别和来源严重失衡。
- 增加真实“难良性”程序，如安装器、更新器、压缩/加壳商业软件、网络工具和管理工具；生成的 Win32 API 良性程序只能作为补充。
- 主测试集保留从未出现在训练中的来源/家族，并分别报告 packed、unpacked、x86、x64 的 PR-AUC、FPR@固定 TPR 和校准误差。

## 建议实施顺序

1. 用现有 IDAPython 提取器跑完本地有标签集，并先做来源/近重复审计。
2. 对 BODMAS 先跑质量 gate，只反编译 `semantic` 路由的代表性子集。
3. 先训练一个仅使用 IDA 结构/API 特征的轻量基线，用于发现数据泄漏。
4. 再训练函数编码器 + MIL 聚合器，并与基线做 source/family holdout 对照。
5. 最后再考虑函数自然语言摘要；摘要适合解释，不应成为第一版检测链路的必要步骤。

本地有标签集的 6 良性 + 6 恶意对照批次也已生成选择清单，但本次 `idat.exe` 在创建日志前统一挂起并触发超时；这些超时未计为样本不可反编译。其 PE 头本身可正常解析，需要先排查本机 IDA 启动/文件访问状态再继续。
